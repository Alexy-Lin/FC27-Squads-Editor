# FC27 Editor 功能计划：补齐缺失球员 · 回归巅峰 · 全员年龄

> 依据：3DM「FC27传奇名单（自由球队）+全员20岁」存档（Squads20261003145848779）与官方档 Squads20261006 的逐人对比；
> 参考项目：`C:\Users\Lin\OneDrive\code\FC26 Editor`（已有成熟的年龄/生日快照、巅峰恢复、传奇补充、名单查看 UI）。

## 0. 已验证的对比结论（本计划的事实基础）

| 项目 | 官方档 Squads20261006 | 传奇档 Squads20261003145848779 |
|---|---|---|
| 球员数 | 21,951 | 21,933 |
| 共有 | 21,689 | 21,689 |
| 官方有、传奇档没有 | 262 | — |
| ├ 真正缺失（补全目标） | **155** | — |
| ├ 同名换 ID（人在，ID 不同） | 49 | — |
| └ 占位/自建记录 | 58 | — |
| 传奇档独有（新增） | — | 244 |
| OVR 被改过的共有球员 | — | 906 |

关键结论：

- 155 个真正缺失全部是低评分边缘/青训/自由球员，最高 OVR 82，没有大牌球星；
- 49 个"同名换 ID"是 FC27 的 `save id = 公开 id + 1` 机制造成的，属于 **ID 重映射/Mod 范畴**，本期不做，只在预览里标注；
- 传奇档并不是"官方档 + 传奇"，它同时把大量球星改成巅峰数值（C 罗 84→92、梅西 89→93），所以"回归巅峰"需要单独做成可控功能；
- 传奇档的 `birthdate` 统一为 `154774`（2006-07-17，赛季内 20 岁），可反推出 FC27 的年龄换算公式。

## 1. 范围与原则

### 本期做

1. **补齐真正缺失球员**：以用户指定的"官方存档"为源，把目标存档里真正缺失的球员（排除占位记录、排除同名换 ID）按原球队/合同关系补回；可预览、可撤销（内存暂存）、另存新档。
2. **回归巅峰**：把现役老将恢复到峰值（默认 FIFA19 峰值口径，参考 FC26 Editor 的 `PeakRestoreService`）；只升不降、排除传奇/ICON、门将属性单独处理、可预览名单。
3. **全员年龄独立功能**：可输入任意年龄（15–40）统一调整，执行前自动写生日快照，支持"恢复原始生日"；不再和"回归巅峰"捆绑。
4. 三块功能都具备 Web UI 卡片 + CLI 参数 + 单元测试 + README 文档。

### 本期不做（明确留到 Mod / 后续）

- 同名换 ID 的 49 人合并/重映射：需要 ID 映射表 + 可能的数据库 Mod，预留接口与数据文件，后续单独排期。
- 存档对比独立页面（本期只作为"补齐球员"的预览数据来源）。
- 女足传奇补充、跨版本（FC26↔FC27）存档迁移。

## 2. 关键技术决策

### 2.1 FC27 ID 映射（必须先做，所有功能共用）

已确认的 FC27 规则：

- 球员：存档 `playerid` = 公开/EA id + 1（如 C 罗 20802 vs 20801），但 `NameResolver.get_official_player_id()` 目前只对 OVR≥85 且有姓名证据的球员应用；
- 球队：`lyxL.teamid` = `assetid` + 2（测试 `test_fc27_mapping.py` 已断言）；
- 生日：`birthdate` = 距 1582-10-14 的天数。

计划新增 `core/id_map.py`，统一提供：

```python
to_official(record) -> int      # 存档 id → 公开 id（优先 player_id_map.csv，其次 pid-1 校验，最后原样）
to_save(official_id) -> int     # 公开 id → 存档 id（默认 +1）
team_official(teamid) / team_internal(assetid)   # 球队 id 互转（+2，带表内校验）
```

`player_id_map.csv` 作为"高置信度覆盖表"继续维护，新增条目只需追加行。

### 2.2 年龄换算（FC27 赛季 2026/27）

```text
birthdate(age) = (2026-age 年 7 月 1 日 - 1582-10-14).days
```

对应常量（写入 `services/birthdates.py`）：

| 年龄 | 生日 | birthdate |
|---|---|---|
| 17 | 2009-07-01 | 155854 |
| 18 | 2008-07-01 | 155489 |
| 19 | 2007-07-01 | 155123（现有代码误当 18 岁，要修正） |
| 20 | 2006-07-01 | 154758 |

- 游戏会隐藏 `birthdate < 125812`（1927-04-01，普斯卡什）的球员，设置时校验并拒绝；
- 3DM 档用的 `154774`（2006-07-17）也在 20 岁区间，两种都可用；默认输出 `154758`，提供"对齐 3DM 值"选项。

### 2.3 补齐缺失球员的搬运规则

源存档（官方）→ 目标存档（传奇档/任意档）：

1. **差集**：按 `playerid` 做集合差；再按"显示名规范化"识别同名换 ID（命中则标 `id_swapped`，不搬运）；按名称/球队特征剔除占位记录（`Player #...`、`Placeholder`、`Custom Team`、`5v5`）。
2. **记录**：复制 `CZUM` 全字段（152 字段），`playerid` 保持源存档值。
3. **归属**：复制源存档 `RrqT`（teamplayerlinks）记录；`teamid` 通过 `assetid` 映射到目标存档的内部球队 id：
   - 映射失败 → 归入自由球员 `111592`，并在结果里列出；
   - `artificialkey` 从目标表现有最大值往后递增；容量不足时报错、不写入。
4. **姓名**：检查 `firstnameid/lastnameid/commonnameid` 在目标存档 `dcplayernames`（`bneD`）/`editedplayernames`（`nQVU`）中是否存在；缺失则从源存档复制对应行（参考 FC26 Editor 的 `names_added` 做法），保证进游戏不显示 `Player #`。
5. **安全**：全部改动走现有 `ChangeSet` 暂存 → 顶部"保存为新存档"；预览阶段不写文件；应用后可再次扫描验证差集为 0。
6. **幂等**：重复应用时差集为空，返回 `added=0`。

### 2.4 回归巅峰的口径（对齐 FC26 Editor）

- 默认：现役（年龄 ≥30）、男足、FIFA19 峰值 OVR ≥85、只升不降；
- 排除传奇/ICON（`data/icon_hero_list.csv`，按公开 id 比对）；
- 同名球员防误伤：国籍 + 身高（±3cm）双重校验；
- 41 项属性（含门将 5 项，只写门将）；总评已达峰值但单项偏低的也恢复；
- 无俱乐部（如内马尔、J 罗）默认仍算现役，可开关；
- 数据源：`data/fifa19_peak.csv`（从 FC26 Editor 复制，827 KB），查找时用"存档 id → 公开 id"映射；
- 输出：预览列表（姓名/年龄/当前 OVR/峰值/可提升项数/球队）+ 应用结果（恢复人数/属性数）。

> 备选数据源（需你确认）：用 3DM 传奇档里的 906 条巅峰值生成 `data/fc27_peak.csv` 作为 FC27 原生口径；建议先按 FC26 Editor 口径落地，后续可加"数据源"下拉。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| FC27 id +1 规则并非全员适用 | 巅峰匹配错人/漏人 | 国籍+身高+姓名三重校验；错配写入 `player_id_map.csv`；预览可见、可只应用子集 |
| 目标存档缺姓名行 | 新球员显示 `Player #` | 补 `bneD`/`nQVU` 行并在预览里报告 `names_added` |
| 球队映射失败 | 球员无队/自由球员 | 回退自由球员 111592 并列出清单 |
| 容量不足（CZUM/RrqT） | 写入失败 | 应用前计算空位，不足直接报错不写 |
| 游戏拒绝异常记录（生日越小越可能隐形） | 球员不可见 | 生日校验 ≥125812；保存后重新加载验证 |
| 传奇档 OVR 已被改过 | 巅峰"只升不降"可能补不到位 | 保留开关；预览显示当前值 vs 峰值 |
| 覆盖原档风险 | 数据丢失 | 沿用"另存新档 + 原档只读"；操作前自动备份提示 |

## 6. 需要你确认的 4 个选择

1. **补人后的归属**：保持官方原球队（推荐）/ 全部放入自由球员？
2. **巅峰数据源**：FIFA19 峰值（推荐，与 FC26 Editor 一致）/ 用 3DM 档反推的 FC27 峰值 / 两者都做、界面可选？
